1. SYSTEM OVERVIEW
================================================================================

The Inventory Management System is a JavaFX desktop application for managing
inventory items (Laptops, Desktops, Accessories) with a role-based approval
workflow. Data Entry users can request additions/updates/deletions, and 
Managers approve or reject these requests.

TECHNOLOGY STACK:
- JavaFX for UI
- MySQL Database (ims_db)
- JDBC for database connectivity
- FXML for UI layout

3. DATABASE CONNECTION LAYER
================================================================================

FILE: Databaseconnection.java
PURPOSE: Centralized database operations - all database interactions go through this class

CONNECTION DETAILS:
- URL: jdbc:mysql://localhost:3306/ims_db?serverTimezone=UTC
- USER: root
- PASSWORD: 0905225438

KEY METHODS:

getConnection()
- Establishes connection to MySQL database
- Loads MySQL JDBC driver
- Returns Connection object for database operations

getAllItems()
- Retrieves all items from Laptop, Desktop, and Accessory tables
- Combines results into InventoryDisplayItem objects
- Used by InventoryListController to display all items
- Returns List<InventoryDisplayItem>

insertRequest(String requestType, String itemType, String itemId, int userId)
- Creates a new request in the Request table
- Used for UPDATE and DELETE requests
- Sets status to 'PENDING' automatically
- requestType: "UPDATES" or "DELETE"
- itemType: "LAPTOP", "DESKTOP", or "ACCESSORY"
- itemId: Serial number of the item

insertNewItemRequest(String itemType, Object item, int userId)
- Creates ADD_ITEM request for new items
- Inserts into Request table with status 'PENDING'
- Inserts item data into appropriate temp table (tempLaptop, tempDesktop, tempAccessory)
- For new items, item_id is set to NULL in temp tables (since item doesn't exist yet)
- Returns the generated request_id

insertUpdateRequest(String itemType, Object item, int userId)
- Creates UPDATES request for existing items
- Finds existing item by serial number
- Inserts updated data into temp table with existing item_id
- Used when updating existing items

approveRequest(int requestId, int managerUserId)
- Manager approves a pending request
- Uses transactions to ensure data consistency
- For ADD_ITEM: Inserts new item into actual table (Laptop/Desktop/Accessory)
- For UPDATES: Updates existing item from temp table data
- For DELETE: Deletes item from actual table
- Updates Request status to 'APPROVED'
- Creates audit log entry
- Cleans up temp table entries after approval
- Uses rollback if any error occurs

rejectRequest(int requestId)
- Manager rejects a pending request
- Deletes entries from temp tables (tempLaptop/tempDesktop/tempAccessory)
- Updates Request status to 'REJECTED'
- Creates audit log entry for rejection
- Uses transactions for safety

getRequestDetails(int requestId)
- Retrieves complete request information
- Returns RequestDetail object with all request data
- Includes temp table data if available
- Used by ApprovalController to display request details

getPendingRequests()
- Returns list of all pending requests
- Used by ApprovalController to show requests needing approval

getPendingRequestCount()
- Returns count of pending requests
- Used by dashboards to display notification numbers

getLowStockCount()
- Counts laptop and desktop items
- Returns count if less than 5, otherwise 0
- Used for low stock alerts on dashboards

getActiveUsersCount()
- Counts users where is_active = 1
- Used to display active user count on Manager Dashboard

getUserActionAlertsCount()
- Counts pending requests of type ADD_ITEM, UPDATES, or DELETE
- Used for alert notifications

getRecentModifications()
- Returns list of recent pending modification requests
- Includes request type, item type, username, and date
- Used by AlertesController to show recent activity

getAuditLogs(String actionTypeFilter)
- Retrieves audit trail entries
- Can filter by action type (ADD_ITEM, UPDATE, DELETE, REJECT)
- Joins with Users table to get usernames
- Used by AuditLogController

getAllUsers()
- Returns list of all users with their roles and active status
- Used by UsermanagmentsController

addUser(String username, String password, String role, boolean isActive)
- Creates new user account
- Returns generated user ID
- Used by UsermanagmentsController

updateUser(int userId, String username, String password, boolean isActive)
- Updates existing user information
- Password can be null to keep existing password
- Used by UsermanagmentsController

setUserActive(int userId, boolean isActive)
- Activates or deactivates a user account
- Used for user management

getFilteredItems(String itemType, String brand, String condition)
- Retrieves items filtered by criteria
- Used by ReportController to generate reports
- Returns List<InventoryDisplayItem>

getAllBrands(String itemType)
- Returns list of unique brands for given item type
- Used by ReportController to populate brand combo box

searchLaptopBySerial(String serialNumber)
- Searches for laptop by serial number
- Returns Laptop object if found, null otherwise
- Used by UpdateItemController and DelateItemController

searchDesktopBySerial(String serialNumber)
- Searches for desktop by tower serial number
- Returns Desktop object if found

searchAccessoryBySerial(String serialNumber)
- Searches for accessory by serial number
- Returns Accessory object if found

cleanupTempTableEntries(Connection con, int requestId, String itemType)
- Helper method to delete temp table entries
- Accepts Connection to work within existing transactions
- Called by approveRequest and rejectRequest

4. DATA MODEL CLASSES
================================================================================

FILE: INVItem.java
PURPOSE: Base class for all inventory items

PROPERTIES:
- itemId: Unique identifier
- condition: Enum (NEW, GOOD, FAIR, POOR)
- createdDate: When item was added

FILE: Laptop.java extends INVItem
PURPOSE: Represents a laptop item

PROPERTIES:
- serialNumber: Unique serial number
- brand: Manufacturer (Dell, HP, etc.)
- model: Model name
- generation: Generation/version
- itemCondition: Condition enum
- haveCharger: Boolean
- haveMouse: Boolean

FILE: Desktop.java extends INVItem
PURPOSE: Represents a desktop computer

PROPERTIES:
- towerSerialNumber: Serial number of tower
- towerGeneration: Generation
- towerModel: Model name
- desktopCondition: Condition enum
- keyboardModel: Keyboard model
- haveMouse: Boolean

FILE: Accessory.java extends INVItem
PURPOSE: Represents an accessory item

PROPERTIES:
- accessoryType: Enum (MONITOR, TOWER, KEYBOARD, MOUSE)
- brand: Manufacturer
- serialNumber: Serial number
- model: Model name
- itemCondition: Condition enum

FILE: InventoryDisplayItem.java
PURPOSE: Data Transfer Object for displaying items in tables

PROPERTIES:
- itemType: "Laptop", "Desktop", or "Accessory"
- serialNumber: Serial number
- brand: Brand name
- model: Model name
- condition: Condition string
- addDate: Creation date
- editBtn: Button for editing (data entry users)
- deleteBtn: Button for deleting (data entry users)

HOW IT WORKS:
- Used by InventoryListController to display items in TableView
- Combines data from different item types into unified format
- Allows role-based UI (edit/delete buttons for data entry users)

PURPOSE: Allows data entry users to delete items

3. If found, displays item information
4. User clicks Delete button
5. Calls Databaseconnection.insertRequest("DELETE", itemType, itemId, userId)

6. REQUEST WORKFLOW
================================================================================

ADD ITEM WORKFLOW:
1. Data Entry user fills Add Item form
2. Clicks Save button
3. AddItemController creates item object
4. Calls Databaseconnection.insertNewItemRequest()
5. System creates Request with status 'PENDING'
6. Item data inserted into temp table (tempLaptop/tempDesktop/tempAccessory)
7. item_id set to NULL (item doesn't exist yet)
8. Manager views request in Approval page
9. Manager clicks Approve:
   - System inserts item into actual table (Laptop/Desktop/Accessory)
   - Updates Request status to 'APPROVED'
   - Creates audit log entry
   - Deletes temp table entry
10. Manager clicks Reject:
    - System deletes temp table entry
    - Updates Request status to 'REJECTED'
    - Creates audit log entry

UPDATE ITEM WORKFLOW:
1. Data Entry user searches for item
2. Updates item details in form
3. Clicks Save button
4. UpdateItemController creates updated item object
5. Calls Databaseconnection.insertUpdateRequest()
6. System finds existing item by serial number
7. Creates Request with status 'PENDING'
8. Updated data inserted into temp table with existing item_id
9. Manager views request in Approval page
10. Manager clicks Approve:
    - System updates actual item from temp table data
    - Updates Request status to 'APPROVED'
    - Creates audit log entry
    - Deletes temp table entry
11. Manager clicks Reject:
    - System deletes temp table entry
    - Updates Request status to 'REJECTED'
    - Creates audit log entry

DELETE ITEM WORKFLOW:
1. Data Entry user searches for item
2. Clicks Delete button
3. DelateItemController calls Databaseconnection.insertRequest("DELETE", ...)
4. System creates Request with status 'PENDING'
5. Manager views request in Approval page
6. Manager clicks Approve:
   - System deletes item from actual table
   - Updates Request status to 'APPROVED'
   - Creates audit log entry
7. Manager clicks Reject:
   - Updates Request status to 'REJECTED'
   - Creates audit log entry

8. KEY DESIGN PATTERNS
================================================================================

1. SINGLETON PATTERN (Databaseconnection)
- All database operations centralized in one class
- Static methods for easy access
- Single connection point to database

2. MVC PATTERN
- Model: Database tables, Java classes (Laptop, Desktop, Accessory)
- View: FXML files
- Controller: Controller classes handle logic

3. TEMPORARY TABLE PATTERN
- Temp tables store pending changes
- Prevents direct modification of actual data
- Allows approval workflow
- Easy rollback on rejection

4. TRANSACTION PATTERN
- approveRequest() and rejectRequest() use transactions
- All operations succeed or all fail (atomicity)
- Rollback on error ensures data consistency

5. OBSERVER PATTERN
- JavaFX ObservableList and FilteredList
- TableView automatically updates when data changes
- Event-driven UI updates

9. ROLE-BASED ACCESS CONTROL
================================================================================

DATA_ENTRY ROLE:
- Can add new items (creates pending requests)
- Can update items (creates pending requests)
- Can delete items (creates pending requests)
- Can view inventory list with edit/delete buttons
- Can view own requests
- Can cancel own pending requests
- Cannot approve/reject requests
- Cannot view audit logs
- Cannot manage users

MANAGER ROLE:
- Can approve/reject requests
- Can view all inventory (read-only)
- Can view audit logs
- Can generate reports
- Can manage users
- Can view alerts
- Cannot directly add/update/delete items
- Must approve all changes
